# 用 AI 更新聊天助手词典

[返回项目首页](../README.md#用-ai-更新词典) · [使用说明](USAGE.md) · [更新记录](../CHANGELOG.md)

这份指南用于让 AI 根据真实聊天制作可检查、可安装的本地词典增量。插件运行时完全离线，不会自动把记录交给 AI，也不会自动安装 AI 返回的文件。

## 1. 准备样本和备份

在 `/chatassist → 本地记录` 确认采集开启，游玩后正常退出或 `/reload`，让游戏保存数据。路径为：

```text
WTF/Account/<账号>/SavedVariables/ChatTranslatorProbe_Mcode.lua
```

其中的 `McodeChatProbeDB.records.missed` 保存漏译或部分翻译，`records.blocked` 保存屏蔽样本。不要把这个账号记录文件误当成插件代码。通用语、含俄文字母等被排除的消息可能没有记录；必要时另行复制完整原句和截图。

更新前备份整个插件目录及已保存的账号存档，放在 AddOns 和 SavedVariables 之外。向 AI 提供的是筛选副本，保留完整原件供自己回退。处理私聊、玩家名或账号信息时，若需要隐藏身份，使用一致的占位名字，保留词序、数字、链接结构及出现的上下文。

## 2. 给 AI 哪些文件

| 材料 | 用途 |
|---|---|
| 当前 `Engine.lua` | 完整词典、别名、语境规则、匹配与显示逻辑，避免重复或冲突 |
| 当前 `Probe.lua` | 查看实际显示模式、设置和聊天接入；通常只需读取 |
| 当前 `ChatTranslatorProbe_Mcode.toc` | 确定版本、加载文件和 Lua 运行环境范围 |
| 筛选后的 SavedVariables 记录或完整原句 | 提供真实输入和当时已有的译文、来源、版本 |
| 你确认的含义与截图 | 解释游戏场景，核对原句、译文和最终显示的差别 |

告诉 AI 你使用 WoW 3.3.5a、默认聊天框还是 ElvUI、当前显示模式，以及目标消息来自组队、喊话、交易还是其他来源。只有截图时，要求它列出不能确认的文字，不猜测缺失字符。

若 AI 能直接访问你的电脑，应先在插件备份副本中修改；没有文件编辑能力时，让它返回完整修改文件或准确补丁，不能只给一张中文词语表就声称已经更新插件。

## 3. 先找原因，再选修改位置

| 现象 | 需要 AI 核对的内容 |
|---|---|
| 原词没有任何匹配 | 是否缺少概念、别名、已确认拼写或复数 |
| 同一个词有时翻译、有时保留 | 职业、团本、技能、交易等语境规则是否满足，是否存在歧义 |
| 词在物品、任务或法术链接内 | 链接是受保护内容，不通过删除链接保护来强行翻译 |
| 保存的 hint 已有中文，聊天框仍是原文 | 优先核对显示模式、原文切换及聊天适配，不重复加同名词 |
| 文字显示问号或特殊单位 | 核对保存原文的真实字符，区分字体、编码和词义问题 |

完整短语、否定词和掉落条件要一起审核。例如 `LFM` 是队伍招人、`LFG` 是玩家求组，`Nothing Ress` 与预留物品含义相反；单独 `res` 不能一律译成“不分”。`SP` 也不能在所有句子里都当作暗牧。

大小写、复数、常见拼写可以共用概念，但只能添加已确认形式。不要机械删除所有单词结尾的 s，也不要用单条喊话推断所有同形缩写的含义。

## 4. 告诉 AI 如何维护词典结构

运行词典编入 `Engine.lua` 的 `P.concepts`，按完整别名匹配并结合语境判断。新增时优先复用已有概念和中文解释；`label`、`aliases`、`guard`、`rules`、`owner`、`category` 等字段需要按现有定义使用，不能添加一个没有匹配实现的新 guard 名称就当作已受限制。

尤其注意：带逐别名 `rules` 的概念，增加 aliases 后还要核对该别名对应的规则；职业或技能词也要核对 owner、颜色类别及同形缩写。新增词不能只靠“AI 说它有这个意思”。

文件中有两条标记：

```lua
-- BEGIN GENERATED WLK LEXICON
-- END GENERATED WLK LEXICON
```

这个区块由工程词典生成。公开插件仓库和安装 ZIP 包含运行文件，不附整个汉化工程的 JSON 词典源和生成器，不能要求普通用户直接运行这些未随包提供的工具。

- 在本地定制中，优先在现有手工词典位置增加概念或别名。确需扩充生成区块中的概念时，可让 AI 在 `END GENERATED WLK LEXICON` 之后、`-- Compile once` 之前保留一段明确的本地增量，并核对它引用的概念存在。不要直接重写整个生成区块。
- 所有增量都必须在词典索引编译之前执行。首词和别名索引在加载时建立，文件加载后才临时添加字段，可能无法参与查询；修改文件后需要重新加载。
- 要合入正式版本时，通过 Issues 或 Pull Request 提供精确增量、原句和验证结果。维护者会把适用的 WLK 数据回填工程内的 `src/translations/chat_wlk_lexicon.json`，审核后生成运行区块；已确认词形按工程中的词形表维护。

本地增量不是用户词典 API。为本地改版保留可区分的版本标识，并使 TOC 的版本与 `P.version` 一致；不随意提高存档 schema。未来正式更新可能覆盖定制文件，需要保留增量清单再合并。

## 5. 要求 AI 交付和验证

使用 README 中的[提示词](../README.md#用-ai-更新词典)，另补充你自己的例句和期望。要求 AI 返回：

1. 新增、修改、复用和暂不确定的概念／别名清单，逐项说明含义及语境。
2. 完整修改文件或可应用的补丁，并列出基线版本、本地版本和实际变更文件。
3. 目标样本的新旧输出，以及能暴露误译的反例；数字、否定、未知条件、链接和颜色控制都要检查。
4. 实际执行的语法、模拟或游戏检查结果。WoW 3.3.5a 使用 Lua 5.1，不能用其他 Lua 版本的通过结果代替。
5. 需要在游戏中复验的场景和恢复原文件的方法。只做静态阅读时，明确写“尚未执行”，不要写成测试通过。

可以要求 AI 至少覆盖以下类型，输出是否翻译由现有规则和修改目的决定，不能把它们全部强制译成中文：

| 样例 | 检查点 |
|---|---|
| `LFM disc` 与 `LFG disc` | 招人与求组方向不混淆 |
| `LFM ICC25 need 1xDisco` | 大小写、连写、数量和原始位置保留 |
| `LFM ICC25 Nothing Ress` | 否定预留不被翻成有预留 |
| `SP 3000`、`res please` | 属性或复活请求不套用招募／分配词义 |
| 带真实物品、成就或法术链接的原句 | 链接结构及链接后的显示颜色保留 |
| 与新增词同形的普通英文句子 | 不因新增缩写而误译日常聊天 |

公开仓库不包含汉化工程的整套回归环境。AI 若只拿到了插件文件，应完成能执行的 Lua 5.1 检查和具体样本对照，并列明缺少的工具或输入，不能声称工程回归全部通过。首次可只处理一小批含义明确的样本，验证后再继续扩充。

## 6. 安装、复验和回退

1. 完全退出游戏，确认备份已经保存。仅在实际 `Wow.exe` 所在客户端的插件目录内替换审核过的文件，不修改账号记录来“制造命中”。
2. 重新登录，用 `/chatassist status` 确认版本与聊天接入，用 `/chatassist demo` 检查基础输出；demo 不会自动覆盖你的新增样本。
3. 在实际使用的聊天来源与显示模式下复验目标句。不要为了测试向公共频道刷屏；可等待同类发言再次出现，再核对保存记录中的原文、hint 和屏幕显示。
4. 同时确认正常聊天、过滤、去重与自定义配色没有受到影响。安装未报错只说明加载没有立即失败，不代表译文正确。
5. 若出现加载错误、误译或显示异常，退出游戏后恢复备份代码；只有存档也被修改或迁移时才恢复对应存档，并注意恢复旧存档会撤回之后新增的记录。重新登录确认原版恢复。

保留 AI 返回的变更清单和验证样例。后续升级正式版时重新审核并合并所需增量，不直接用一份旧 Engine.lua 覆盖新版本全部逻辑。
